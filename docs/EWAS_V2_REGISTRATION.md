## 0. Question
(a) Does the embedding recognise EWAS hits relative to unlisted CpGs of the same chromosome and probe type (MAIN, technical matching)? (b) Does it still do so after controlling for coarse genomic context (S1)? Primary comparison: candidate `regulatory_histone_dnase_v1` vs CpGPT-large (512 D); secondary vs DeepCpG-128. Both directions are shown; no task is selected by results.

## 2. Definitions (exact)
**Universe**: 408,399 CpGs of `outputs/encode_atlas_v1/loci.parquet` (chr1-22; row order = store row order). Covariates (`data/derived/bioval_v2/covariates/universe_covariates.parquet`) are joined by `cpg_idx` (its row order differs). Set `.npy` files use the canonical id `encode_many(chr,pos)`, mapped to universe rows through the registry coordinates; sha256 of all 16 set files is pinned (`exp5_pins.json`, also in the manifest); a mismatch aborts. Probe type = covariates `probe_type` (I=1, II=2; 6,429 unknown, 1.6%).
**Positives** = set members present in the universe. Unknown-probe-type positives are dropped (counted).
**MAIN background** (`design.technical_background`): strata (chromosome, type) sorted; positives in sorted universe-row order; for each stratum `default_rng(17)` draws without replacement as many backgrounds from the sorted eligible rows (not in the union of all sets, not positive, known type) as there are positives; positives of an undersupplied stratum are `unmatched` (counted; all counts are 0 here). One `default_rng(17)` per task, consumed over sorted strata.
**S1 background** (`design.context_matched_background`): exact chromosome x type x island class (island/shore/shelf/open_sea). Covariates (gc_content, cpg_density_hg38, tss_dist; tss_dist is already log10-scale in the table, used as stored) standardized with mean/sd (ddof 0) over probe-known universe rows (stored in `s1_standardization.json`). Within a stratum positives are processed in `default_rng(17).permutation` order; each takes the Euclidean-nearest unused eligible background within Euclidean distance <= 0.25 (ties: smaller row); unmatched positives are dropped and counted. S1 has its own pair file, N and tier (the MAIN tier is unchanged).
**Folds**: fold of a pair = fold of its chromosome. Outer test fold f; train = the other 4 folds; **nested plan** (`nested_cv_plan.json`): inner = leave-one-train-fold-out (4 inner folds), 5 C values -> 105 fits per task and design (5 outer x (5x4 inner + 1 refit)).
**Probe**: `LogisticRegression(penalty=l2, solver=lbfgs, class_weight=None, max_iter=10000)`; per outer fold the scaler is fit on the outer-train rows only and reused (not refit) in the inner CV; C = argmax of the mean inner-fold AUROC (ties -> smaller C); refit on all outer-train rows; OOF decision score for the outer test fold. Implemented by the imported `chrom_probes.logistic_blocked_cv`; the assertion `assert_blocked` guards fold leakage. Row layout: positives then backgrounds; pair i = rows (i, P+i).
**Metrics** (pairs i=1..P, scores s): AUROC = (sum of ranks of the positives - P(P+1)/2)/P^2 over the pooled 2P rows (ties mid-rank); concordance = (1/P) sum_i [1(s_pos,i > s_neg,i) + 0.5 1(s_pos,i = s_neg,i)]; AUPRC = average precision (prevalence 0.5, sensitivity only).
**Bootstrap**: `BlockBootstrap(names=sorted chr1..chr22, B=1000, seed=17)` = `default_rng(17).integers(0,22,(1000,22))`; replicate b gives each chromosome block a multiplicity m_b,c; every pair whose EWAS CpG lies in block c gets weight m_b,c (both members share the chromosome, so pairs are never split); AUROC is the weighted AUROC (exactly equals concatenating the resampled rows; tested), concordance the weighted mean. The same draws are used for every arm, task, design and metric; blocks without pairs contribute nothing. CI = 2.5/97.5 percentiles; contrast delta = candidate - comparator, replicates paired by draw; p two-sided with the (1+k)/(1+B) floor (descriptive). With 22 blocks CIs are coarse.
**Family summary** (`metrics.family_summary`): per design x contrast x metric x family x tier x scope: number of tasks with CI>0 (candidate better), CI<0, CI containing 0. Families: exposure (smoking, BMI), aging (age EWAS + Horvath, PhenoAge, Hannum), disease (the 10 disease sets). Scope `independent` (primary) excludes non_independent tasks, which are counted through their partner; scope `all` includes them. Primary reading = main-quality tier; exploratory/insufficient rows are listed separately. No multiplicity adjustment, no pooling, no aggregate.
**Reading S1**: per task and arm AUROC main vs S1 and the difference; sign agreement of candidate - CpGPT between main and S1; no pre-set attenuation threshold. Sequence arms are also neutralised by S1.

## 6. Bugfix versus methodology policy
Design-defining files (this document, the spec, the manifest, and thereby sets, pairs, folds, plan, draw table) cannot change after the tag (gate 4); a change is a declared amendment with its own tag and is reported next to the original. Code may be fixed after the tag only for bugs that do not change any design parameter (the run manifest records `code_changes_since_tag`); any change of matching, probe, grid, folds, metrics, bootstrap or contrasts is methodology and needs an amendment. Non-converged fits (n_nonconverged_fits>0) are not silently accepted: `contrasts` refuses unless `--allow-nonconverged`, in which case affected cells are flagged; raising max_iter for ALL arms is the only allowed remedy, declared as an amendment. No tuning on results; after EXECUTED no design parameter changes.

## 7. Pre-run checklist
(1) Orchestrator commits this document, spec, manifest, code and tests; (2) creates tag `ewas-v2-protocol-freeze-v1`; (3) `run_ewas_v2.py gate` all PASS (reads each store once for sha256 and CpG coverage); (4) `build_design_artifacts.py --check` reports identical; (5) run arms one heavy process at a time (`nice -n 10`, <=4 threads; two arms may run concurrently only within an 8-thread total, state is derived from per-arm manifests); (6) `contrasts`, then `report-inputs`. Estimated cost (analytic, conservative; 105 fits x 16 tasks x 2 designs per arm): candidate ~34 min, CpGPT-512 ~67 min, DeepCpG-128 ~17 min, functional ~34 min at 4 threads (a synthetic timing gave about 2e-9 s per row-dim-iteration, estimate uses 5e-9 and 150 iterations).

## 8. Caveats
EWAS probes come from array content biased to promoters/islands (shared by positives and backgrounds; MAIN does not control it, S1 does). EWAS cohort overlap with GEO/TCGA cohorts is UNVERIFIED; download dates of EWAS Catalog/Atlas are unrecorded (UNVERIFIED). CpGPT is methylation-pretrained (direct supervision), so an advantage on blood EWAS may reflect that. Negatives are unlisted, not unassociated. Sets overlap (section 3). EWAS Catalog sets use p<1e-7, Atlas sets no uniform cutoff; clocks are selected predictors, not association hits. The 450K universe excludes EPIC-only hits (age: 300,698 ids, 2,194 in the universe). The candidate SVD is label-free and fit on chr1-19 (chr20-22 transformed only); candidate store float32 vs float16 comparators (all cast to float32). With 22 blocks the CIs are coarse; small tasks have blocks with 0-2 pairs. No multiplicity adjustment: p values and CIs are descriptive. S1's Euclidean caliper drops 2-6% of positives (own N/tier reported).

## 9. Freeze ordering and the exp5 completion
This protocol and its design artifacts are fixed before any candidate result on these sets is inspected. `docs/EXP5_CANDIDATE_COMPLETION_PLAN.md` (discovery completion on the old Exp5 design) is NOT run before the tag; its results, when they exist, were not available when this protocol was frozen and cannot motivate changes to it. If the exp5 completion is run before the EWAS-v2 arms, the committed registration (this statement) must be amended to say so before any EWAS-v2 result is read. Any information seen by the authors before the freeze (the frozen bioval-v2 and exp5 comparator results for CpGPT/DeepCpG/functional on the old design) is acknowledged: no candidate score on the EWAS-v2 sets has been seen.
