# CpGRepresentationBenchmark

Controlled benchmark of **patient-agnostic CpG locus representations** for methylation modeling.

The primary question is whether a CpG representation derived from reference-genome functional annotations is more useful than locus representations extracted from genomic or methylation foundation models. The benchmark is **representation-controlled**: the downstream model is fixed and only the patient-agnostic CpG representation changes.

The repository now separates two experimental tracks:

- `native_frozen`: the CpG/locus embedding exactly as extracted from the published model;
- `proxy_aligned`: the same patient-agnostic source after optimization with the shared train-locus-only methylation proxy.

The original chr1 masking experiment remains executable, while the V2 layout adds proxy training and shared downstream evaluation for masked reconstruction, age, mortality and disease prediction, including sparse/masked methylome sweeps. See `docs/BENCHMARK_V2.md`.

## Current executable scope: TCGA array, chromosome 1

The available NTv3-pre atlas currently contains chr1 only. Therefore the initial benchmark is intentionally restricted to **TCGA-array CpGs on chr1 for both representations**.

This is the correct deployment choice now: it lets us validate the complete protocol without spending compute on a genome-wide NTv3 extraction. Once the benchmark is stable, the main paper experiment should be expanded beyond chr1 so the final biological claim is not chromosome-specific.

Both arms share exactly:

- TCGA patient split;
- chr1 CpG universe;
- persistent train/held-out CpG split;
- masking percentages;
- reconstruction architecture;
- optimizer/training budget;
- leakage-safe prior policy;
- metrics.

Only the CpG representation changes.

## 1. Bootstrap and preflight

From the repository root:

```bash
python scripts/bootstrap_local_data.py
```

The script validates:

- `tcga_array_official_full.h5` (`beta`, `cpg_idx`, `sample_name`);
- alignment with `array_cpg_map.parquet`;
- the number of TCGA-array CpGs on chr1;
- the existing NTv3-pre atlas structure and embedding dimension;
- **complete NTv3 coverage of the dataset-defined chr1 CpG universe**;
- availability of the existing functional locus store and encoder checkpoint.

It also creates the functional symlinks and writes:

```text
data/local_manifest.json
```

If NTv3 does not cover every required chr1 CpG, preflight exits with code 2 rather than silently changing the benchmark universe.

## 2. Materialize the functional chr1 representation

The first Functional run can generate the representation automatically:

```bash
CUDA_VISIBLE_DEVICES=0 python scripts/run_masking_benchmark.py \
  --config configs/experiments/masking/functional_generate_if_missing.yaml \
  --mode all
```

On the first run this builds:

```text
data/cache/representations/functional_annotations_chr1.h5
```

with the canonical contract:

```text
/cpg_idx    int64   [N]
/embedding  float16 [N, 256]
```

Subsequent runs can use `functional_precomputed.yaml`.

## 3. Run NTv3-pre on the same protocol

```bash
CUDA_VISIBLE_DEVICES=0 python scripts/run_masking_benchmark.py \
  --config configs/experiments/masking/ntv3_precomputed.yaml \
  --mode all
```

The NTv3 loader can auto-detect common existing-atlas dataset names such as:

```text
/cpg_idx + /embedding
/ids     + /emb
```

The actual resolved keys are recorded in `representation_manifest.json`.

Both configurations point to the same persistent locus protocol:

```text
data/protocols/tcga_array_chr1_masking_seed17_holdout20.npz
```

so the Functional and NTv3-pre arms are evaluated on the exact same CpGs.

After materializing the shared proxy embeddings, the same masking runner can be used without any architecture change:

CUDA_VISIBLE_DEVICES=0 python scripts/train_proxy_representation.py \

CUDA_VISIBLE_DEVICES=0 python scripts/run_masking_benchmark.py \
  --config configs/experiments/masking/functional_proxy_aligned.yaml --mode all
CUDA_VISIBLE_DEVICES=0 python scripts/run_masking_benchmark.py \
  --config configs/experiments/masking/ntv3_pre_proxy_aligned.yaml --mode all

The two proxy encoders are fitted on the same train-locus protocol and never use downstream held-out CpGs for proxy loss or checkpoint selection.

## Masking benchmark

Two evaluation views are first-class:

1. `seen`: masked targets come from the train-locus universe;
2. `unseen_locus`: targets are a disjoint CpG split never used as reconstruction-training context or target.

For `unseen_locus`, held-out CpG methylation is also excluded when fitting the prior. Held-out loci use one global prior estimated from **train patients × train loci only**.

Default masking sweep:

```text
15%, 30%, 50%, 70%, 90%
```

## Representation-controlled comparison

The downstream reconstruction model is fixed:

```text
observed locus representation + observed methylation residual
        -> tokenization
        -> DeepSets patient encoder
        -> patient embedding

target locus representation + patient embedding
        -> residual decoder
        -> sigmoid(target prior + delta)
```

A learned adapter maps raw representations to a common latent width. Before the final paper comparison, we should additionally implement the fixed-dimensional train-locus PCA/IncrementalPCA control described in `docs/BENCHMARK_DESIGN.md`, so different raw embedding dimensions cannot create a parameter-count confound.

## Important interpretation of unseen loci

The current `unseen_locus` protocol guarantees that held-out CpGs are unseen by the **downstream reconstructor** and do not leak through the methylation prior.

A stronger claim that loci are unseen by the **representation encoder itself** requires auditing/retraining the functional encoder so its methylation-supervised fitting also respects the same locus split. Until that is verified, describe this arm as downstream-unseen rather than strict representation-OOD.
